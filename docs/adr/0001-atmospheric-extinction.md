# ADR-0001: 大気消光を SQM の値に補正する

- 状態: 採用
- 関連: Issue #12、`docs/specs.md` §7.4

## 背景

基準星方式の式は `SQM_raw = 2.5·log10(L_star / L'_sky) + m₀` で、`m₀` は基準星のカタログ V 等級（大気圏外の値）である。ところが `L_star` は大気を通って減光した星の光を測っている。地上で見た星の等級は `m₀ + k·X`（k: 消光係数、X: 大気質量）なので、`SQM_raw` は `k·X` だけ明るく（数値は小さく）出る。

旧い仕様書（§7.2・§9.1）は「基準星と背景が同一大気経路のためほぼキャンセルされる」と書いていたが、**これは誤り**だった。ゼロ点 ZP は星と背景に共通なのでキャンセルされるが、消光は共通ではない。背景は大気の中で光っている（光害の散乱光・大気光）ので、星のようには減光されない。

求めたい値は「地上で見た空の明るさ」である。Unihedron SQM も消光補正をしないので、それと同じ基準になる。

## 決定

**`SQM = SQM_raw + k·X`** で補正する。

1. **大気質量 X** は Kasten & Young (1989) の式で、基準星の高度から求める。高度 10° 未満のフレームは X を求めず（NaN）、補正に使わない。
2. **高度**はフレームごとに、基準星の RA/Dec（J2000）、観測地、露出の中央時刻から計算する（Meeus の JD・GMST）。計算はすべて `sqm_math.js` の純粋関数にして Node でテストする。
3. **露出の中央時刻（UTC）** は FITS キーワードから、`DATE-AVG` → `DATE-OBS` と `DATE-END` の中点 → `DATE-OBS` ± `EXPTIME`/2 の順で求める。最後の場合、`DATE-OBS` のコメントに "end" があれば終了時刻とみなして引き、なければ開始時刻とみなして足す（DWARF は "Time end of exposure" で終了時刻を書く）。
4. **観測地**は `SITELAT`/`SITELONG` → `OBSGEO-B`/`OBSGEO-L` → ダイアログの手入力の順で求める。手入力は、ヘッダに観測地が無いフレーム（DWARF など）の受け皿で、変更したその場で `Settings` に保存する。
5. **基準星の座標**は、基準星を選んだときの天体位置の解から得た RA/Dec を使い、無ければ Sesame の検索結果を使う。どちらも無ければ補正しない。
6. **補正に使う X** は、L_star のフィットに使ったフレーム（飽和で除外されていないもの）の X の平均。
7. **k** の既定は 0.20 mag/airmass。ダイアログで編集でき、測るチャンネルに対する値として扱う。「補正するか」のチェックボックスを置き、既定は ON。
8. **補正できないときも Analyze は止めない。** SQM に "not corrected for atmospheric extinction" の注記と理由を付ける。
9. 歳差は補正しない（下記）。

## 却下した案

### AIRMASS / CENTALT / OBJCTALT キーワードを使う案

ヘッダに大気質量や高度が入っていれば、計算せずに済む。却下した理由は、**基準星の値ではない**こと。これらは視野中心や架台が向いている方向の値で、基準星は視野の端にあることもあり、高度が数度ずれうる。また書き込むソフトによって意味が違う（開始時の値、露出中の値、望遠鏡の報告値など）うえ、書かないソフトもある。計算なら、どのソフトのデータでも同じ定義で X が出る。

### XISF のプロパティ（`Observation:Time:Start` など）を読む案

XISF のプロパティは型付きで、本来はこちらが推奨される。しかし今回は FITS キーワードで足りる（WBPP の出力にも FITS キーワードが入っていることを確認した）。読む経路が 2 つになるとテストも優先順の説明も増えるので、今回は読まない。必要になったら足す。

### チャンネルごとの k（R・G・B で既定値を変える）

波長が短いほど消光は大きいので、理屈の上では妥当である。しかし既定値の根拠にできる実測が手元に無く、数字を置くと、確かめていない精度を持っているように見える。k は編集できるので、実測値を持つ人はそれを入れられる。実測がそろったら見直す。

### 歳差の補正

基準星の座標は J2000 で、観測時点の座標ではない。2026 年で約 22′ ずれる。却下した理由は、**効果が無視できる**こと。高度 30° で、22′ のずれによる高度の変化は大気質量で約 1%（X = 2 のとき 0.02）、補正量にして 0.005 mag 以下で、k の不確かさ（±0.05 で X = 1.5 のとき ±0.08 mag）より 1 桁以上小さい。式と変換を足すと、テストするものが増える割に精度は変わらない。

### 補正できないとき Analyze を止める案

観測地か時刻が無いと補正できない。止めると、**DWARF のように観測地キーワードの無いデータが、手入力しない限り使えなくなる。** 補正前の SQM は、注記つきで出せば意味がある（相対比較には使える）。止めずに、補正できなかったことと理由を結果と CSV にはっきり書く。

## 代償

- **k の既定値（0.20）は、その夜の透明度とは限らない。** 補正量は `k·X` なので、k が ±0.05 ずれると X = 1.5 で ±0.08 mag ずれる。補正前より近づくことが多いが、補正後の値に確からしさが増えたように見えやすい。結果に k と X を併記し、仕様書にこの不確かさを書いた。
- **観測地を入力しないと補正されない。** 手入力が要るのは、DWARF のようにヘッダに観測地が無い場合である。入力を忘れると、注記つきで補正前の値が出る。
- **フレームごとに X を求めるので、読み取りが 1 つ増える。** `DATE-OBS` の意味が書き手で違う（開始か終了か）ため、コメントの "end" という文字列に頼っている。コメントを書かない、または別の言い方をするソフトでは、開始時刻として扱われ、露出時間の半分（数秒〜数十秒）ずれる。X への影響は小さい（恒星時で 15″/s なので 30 s で約 0.1°）。
- **高度 10° 未満の測定は補正されない。** 低空では式が信用できないため。
- **補正前の SQM と補正後の SQM が混在すると比較できない。** 旧い版の結果は補正前の値であり、この版のものと並べるときは `SQM_uncorrected` で揃える。
